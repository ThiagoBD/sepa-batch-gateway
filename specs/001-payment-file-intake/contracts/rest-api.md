# REST API Contract: Payment File Intake

This is the design contract. The runtime source of truth is `api/openapi.yaml`, a snapshot generated by springdoc and checked by `OpenApiContractTest`; when they differ, the snapshot wins and this file is updated in the same PR.

## Headers

- `X-API-Key` (required on every endpoint below): the client's API key.
- `X-Correlation-Id` (optional): accepted only if it matches `[A-Za-z0-9-]{1,64}`, otherwise replaced by a generated UUID. Always returned in the response and in every problem body.

Public, no key: `GET /actuator/health`, `/v3/api-docs`, `/swagger-ui.html`.

## Endpoints

| Method and path | Request | Success | Errors (RFC 9457) |
| --- | --- | --- | --- |
| `POST /v1/payment-files` | multipart: `file` (required), `sha256` (optional, hex, compared without regard to case) | 201 + `Location` + PaymentFile with its final status. 200 + `Idempotent-Replayed: true` when the content already exists for the client | 400 `invalid-request`, 401 `unauthorized`, 413 `file-too-large`, 415 `unsupported-media-type`, 422 `checksum-mismatch`, 500 `internal-error` |
| `GET /v1/payment-files/{id}` | — | 200 PaymentFile | 400 `invalid-request` (id is not a UUID), 401, 404 `payment-file-not-found` |
| `GET /v1/payment-files/{id}/status-report` | `Accept: application/xml` | 200 pain.002.001.10, `Content-Disposition: attachment; filename=pain002-{id}.xml` | 401, 404, 409 `report-not-ready` (reserved for V2) |
| `GET /v1/payment-files/{id}/instructions` | `status` (ACCEPTED or REJECTED), `page` ≥ 0, `size` 1–200 (default 50) | 200 page of Instruction, ordered by `sequenceNo` | 400 `invalid-parameter` with `errors[]`, 401, 404 |

An invalid file is not a 4xx: it answers 201 with status REJECTED and a pain.002, because the file was received and the client needs the report (ADR-0008). A resource of another client answers 404, never 403 (RN-14).


Money is always a decimal string, so no JavaScript client rounds it. `rejectionDetail` is filled only for FF01: the line, column and element path of the first XSD violation, never the offending value (RN-03).

```json
  "size": 50,
```

Full IBANs and names appear only here, and only to the file's owner; they never appear in logs.

## Problem types

Every error is `application/problem+json` with `type` = `https://api.quayside.example/problems/{slug}`, `title`, `status`, `detail`, `instance` and the extension `correlationId`. Stack traces never leave the server.

| Slug | Status | When |
| --- | --- | --- |
| `invalid-request` | 400 | Missing or empty `file` part; id that is not a UUID |
| `invalid-parameter` | 400 | Query parameter out of range; lists `errors[]` |
| `unauthorized` | 401 | Missing, unknown or inactive API key |
| `payment-file-not-found` | 404 | Unknown id, or a file of another client |
| `report-not-ready` | 409 | File still RECEIVED (reserved for asynchronous processing in V2) |
| `file-too-large` | 413 | `file` part above 20 MB (20,971,520 bytes) |
| `unsupported-media-type` | 415 | Request is not multipart |
| `checksum-mismatch` | 422 | `sha256` field differs from the content |
| `internal-error` | 500 | Any unexpected failure; the whole file is rolled back |

```json
  "type": "https://api.quayside.example/problems/checksum-mismatch",
```
